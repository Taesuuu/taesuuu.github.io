AI Cases.

AI 도구를 실무에서 어떻게 검증하며 썼는지, 대표 사례 두 가지로 설명합니다.

사례 1 · uCMP 리포트 성능, 데이터 정합성 문제 해결.

반복문 안에서 매번 개별 SQL을 호출하던 게 지연의 원인이었습니다. 사전 일괄 조회와 메모리 캐싱으로 구조를 바꿔 리포트 속도를 약 30% 단축했습니다.

Description.

리포트 생성 중 타임아웃이 발생하고, 원인 불명의 메트릭 누락 장애도 월 1~2회 재발했습니다. Codex, GPT에 수집 로직을 전달해 가설을 도출한 뒤 직접 DB 쿼리로 검증해, 반복문 안에서 SQL을 매번 개별 호출하는 패턴을 확인했습니다.

What did I do.
  • 반복문 진입 전 데이터를 일괄 조회해 Map에 캐싱, 반복문 안에서는 메모리 조회만 수행하도록 리팩토링
  • 기존 로직과 병행 운영, AI 결과 비교 검증 후 전환 (롤백 리스크 최소화)
  • OCI API의 간헐적 메트릭 누락도 함께 발견, 재조회 방어 로직 추가 → 장애 재발 0건
  • 리포트 속도 약 30% 개선
원칙AI가 제시하는 원인·해법은 가설로 취급, 직접 DB 쿼리와 로그로 검증한 뒤에만 반영

UNO-Proxy · Envoy 기반 Proxy 운영 도구.

저작권 등록 · 2026.04 – 현재

운영 서버에 검증되지 않은 설정이 바로 반영되는 위험을 없애기 위해, Master가 미리 만들고 검증한 설정만 Agent에 배포하는 구조로 설계했습니다.

Description.

1개 고객사 요구사항(기존 Gateway UI에서 Proxy까지 통합 관리하고 싶다는 니즈)으로 시작해 3개월 데드라인 안에 구축했습니다 (Envoy 오픈소스 코어 활용, Nginx Plus 등과 비교 후 선정).

What did I do.
  • Master-Agent 구조로 설계: Master가 xDS·Envoy 설정을 사전 생성, 검증 후 Agent(Spring)에 배포
  • 운영 서버에는 검증된 파일만 배포해 안정성 확보
  • Envoy hot restart로 SSL 인증서 무중단 자동 갱신 구현
  • 컴퓨터프로그램저작물 저작권 등록 완료
Tech Stack.
EnvoySpringJPAQueryDSLGoJMeterTLS/SSL
